Ask for code, get code.

## What's new

- **Code requests get the code itself.** "create and reverse a string in rust" used to come back as `reverse string`, or, with longer answers, as an explanation of how you'd do it. Now you get working code, on as many lines as it needs, whatever the answer length:

  ```rust
  let s = "hello";
  let reversed: String = s.chars().rev().collect();
  println!("{}", reversed);
  ```

  Paragraph length adds brief comments.
- **Inkling knows the language from where you are.** On the Rust Playground, "create and reverse a string" gives Rust. The same goes for the Go and TypeScript playgrounds, .NET Fiddle, JSFiddle, CodePen, Google Colab, Compiler Explorer, OneCompiler, Programiz, LeetCode, Replit, and a code file open in your editor (`.py`, `.rs`, `.ts`, …). A language you name always wins.
- **Code arrives exactly as written.** It's pasted rather than typed, so editors don't re-indent it or add extra closing brackets. Your clipboard is put back right after, and the code stays out of clipboard history.
- **Terminals stay safe.** Every Enter runs a line there, so code requests in a terminal still get a single command.
- **"Do it", not "here's how".** For anything you ask Inkling to write or do, a reply, a list, a translation, it gives the finished result rather than describing it.

## For developers

**Code detection** (new `Ai/CodeIntent.cs`)
- `CodeDetector.Detect(request, url, title, extension)` returns a `CodeIntent(Language, Source)`, or null when the request isn't for code. In order:
  1. **A language named in the request.** "in/using <lang>", "with/for <lang>", or "<lang> function/code/script/query/…". The single-letter C and R, and "shell", only count after "in"/"using", so "words that start with r" and "vitamin c" don't trigger it.
  2. **A code site.** The request must read like a task, meaning it contains a doing verb and isn't a question ("what is a lifetime" stays text). `CodeSites` maps a host plus an optional path start to a language: `play.rust-lang.org`, `go.dev/play`, `typescriptlang.org/play`, and so on. OneCompiler and Programiz take the language from the path. LeetCode, Replit, github.dev, vscode.dev, StackBlitz and CodeSandbox leave the language to the model. When the address isn't known, the page title is used ("Rust Playground").
  3. **A code file's extension** (from `OpenFile`, 0.4.5), again for task-like requests.
  4. **A code verb with a code noun** ("write a function that…"), with the language left to the model. "script" alone doesn't count, so "write a script for my video" stays text.

**Prompt** (`Ai/Prompt.cs`, `AppConfig.cs`)
- The system prompt gains: produce the finished result, never describe how to do it or name the task. Saved configs with the previous default are upgraded on load. `PreviousSystemPrompt` joins `OldSystemPrompt`.
- `Prompt.Build(…, code, terminal)` adds `Code language here: Rust (the page is the Rust Playground)`. It also swaps the length line for "write the actual code, complete and working … as many lines as it needs, normal indentation, nothing before or after it", tuned per length. In a terminal it asks for a single command line.
- The Short length line now reads "as short as possible while still doing what is asked".
- Two new few-shot examples: a 7-line indented Python `is_prime`, and a written reply. `AppConfig.Load` adds missing examples, matched by request text.

**Multi-line answers** (`CaptureController`, `Ai/ChatApiBackend.cs`, `Ai/OutputCleaner.cs`)
- `RequestTrace.Multiline` is true for code outside a terminal (`SelectionSkipApps`). When it's set:
  - the stream isn't cut at the first line;
  - `max_tokens` is at least 1536;
  - the answer is cleaned with `singleLine: false`.

  `RequestTrace.Kind` ("code"/"text") shows in the timings report and log.
- `OutputCleaner.Clean` for multi-line answers:
  - keeps indentation and inner blank lines;
  - removes only the indentation every line shares;
  - keeps the first line's indent inside a code fence (the fence content was being `Trim()`ed);
  - strips `$ ` prompts only when every line has one.

  One-line answers are cleaned as before.
- New `InputSender.PasteTextAsync`:
  1. snapshots the clipboard (`SelectionReader.Snapshot`, now internal);
  2. sets the text with CRLF line endings, plus the `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory = 0` and `CanUploadToCloudClipboard = 0` formats;
  3. sends Ctrl+V and waits 250 ms;
  4. restores the clipboard.

  Multi-line answers use it; everything else is still typed key by key. Retry stays off for multi-line answers.
- `ForegroundContext.Read` returns a `Where` record (app, process, title, URL, file), so the controller can use the page and file for code detection. `Compose(Where, cfg)` builds the context from it.

**Benchmark** (`Bench.cs`, `bench/questions.json`)
- New `--length short|sentence|paragraph`.
- Apps can carry a page `url`.
- Questions go through the same file, URL and code detection as the app, and multi-line answers are graded whole.
- 9 new code questions:
  - Rust on the Rust Playground without naming the language;
  - Rust by name in Notepad;
  - Go on the Go Playground;
  - Python, JavaScript and C# in editor files;
  - TypeScript by name in a browser;
  - SQL;
  - Bash in a terminal, which must stay one line.

  The answers must match regexes for the key API, and be multi-line where expected.
- Results:
  - code questions in all three lengths: 54/54 across Nemotron 3.5 Bolt and Laguna XS 2.1;
  - full benchmark (51 questions, Short): Nemotron 100% (51/51), Laguna 96% (49/51);
  - Laguna's misses were a Python date one-liner and the German translation it also missed before. The previous run was 95% for both.
