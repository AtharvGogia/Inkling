Rewrite what you've selected, run a model on your own PC, and watch longer answers appear as they're written.

## What's new

- **Rewrite selected text.** Select some text and press **Ctrl+Alt+Enter**, type what to change ("make it more formal", "translate to german", "add type hints"), and press Enter. The selection is replaced with the rewritten version, line breaks and indentation included. The common ones are one key away:
  - **1** fixes the grammar (so does Enter on its own);
  - **2** makes it shorter;
  - **3** makes it more formal;
  - **4** makes it friendlier;
  - **5** turns it into bullet points.
- **Ask about selection is now Ctrl+Alt+W.** Ctrl+Alt+Enter went to rewriting. If you never changed the shortcut, it moves to Ctrl+Alt+W automatically; if you set your own, it stays as it is.
- **Run a model on your PC.** Settings → Model → *Or run a model on this PC* works with [Ollama](https://ollama.com/), LM Studio, or any server with the same OpenAI-style API. Nothing leaves your computer, it works offline, and there's no rate limit. The model is loaded the moment you press the shortcut. Models that like to think before answering are told to skip it, so short answers stay short. Switch between your local model and NVIDIA's from the tray's Model menu.
- **Longer answers appear as they're written.** With *A sentence or two* or *A paragraph*, the answer starts showing up right away instead of all at once at the end. This doesn't happen in terminals or for code, and you can turn it off in Settings → Typing.
- **Calmer dots.** The `...` while Inkling thinks moves at a third of the speed.

## Fixes

- In Word, Outlook, PowerPoint, OneNote and Excel, a stray period could be left in front of the answer. Office's AutoCorrect turns `...` into a single `…` character, which threw off the erasing. Those apps now get `···` instead.
- In VS Code (and Cursor, Windsurf, VSCodium), code now comes as a single line. Their built-in terminal can't be told apart from the editor, and several lines pasted into a shell could run.
- In Office apps, *Try again* isn't offered after an answer that AutoCorrect may have changed (`--`, `(c)`, `->`…), since erasing it could take the wrong number of characters.
- Holding a shortcut a moment too long could cancel what it had just started.
- After switching models, "Use a local model" stayed ticked in Settings even when NVIDIA's API was in use again.
- Pasted code and rewrites could, in a busy app, paste your previous clipboard instead.
- Code answers and rewrites waited for the server to finish its bookkeeping before typing, which could add seconds.

## For developers

**Rewrite** (`CaptureController`, `Ai/Prompt.cs`, `Ai/OutputCleaner.cs`)
- New `State.Instructing`. `BeginRewrite` copies the selection after the hook returns (`SelectionReader.ReadAsync`). `OnInstructionKey` then swallows every key, so the app's selection is never replaced. It builds the instruction with `KeyTranslator`, maps 1–5 (and Enter with an empty instruction) to `Prompt.RewritePresets`, and cancels on Esc, the shortcut, a window switch or a click.
- `RunRewriteAsync` sends `Prompt.BuildRewrite(context, selected, instruction)`, with the selection between `<<<` `>>>`. It cleans the reply with `OutputCleaner.CleanRewrite`:
  - keeps indentation;
  - restores the selection's leading indent if the model dropped it;
  - keeps the final line break when whole lines were selected;
  - drops fences, echoed markers and added quotes.

  The result is pasted with `InputSender.PasteTextAsync`. If the target changed meanwhile, it goes to the clipboard instead. `RequestTrace.MaxTokens` raises the output limit for long selections.
- `RewriteHotkey` (default Ctrl+Alt+Enter); `SelectionHotkey` default is now Ctrl+Alt+W. `AppConfig.Load` moves a saved `SelectionHotkey` of Ctrl+Alt+Enter to the new default when the file predates `RewriteHotkey`.

**Local models** (`Ai/ChatApiBackend.cs`, Settings)
- `Backend = "local"` reuses `ChatApiBackend` with `LocalBaseUrl` (default Ollama's `http://localhost:11434/v1`) and `LocalModel`. It sends no key and skips the rate limiter.
- `WarmLocal` sends a one-token request on the shortcut, so the model is in memory by Enter. It's skipped if the same model was used in the last 3 minutes.
- `AppConfig.RequestTimeout` is at least 120 s for local, because loading a model from cold took 27–57 s here.
- Requests carry `reasoning_effort: "none"`. Without it, qwen3.5 spent about 60 s and its whole token budget thinking and returned nothing. The alternatives behaved like this:
  - `think: false` was ignored;
  - `reasoning_effort` worked, and llama3.1 accepts it too;
  - a server that answers 400 is retried without it, and remembered.

  An answer with only reasoning now raises a clear error instead of "Empty answer".
- Connection errors and missing models get their own messages. `ListLocalModelsAsync` fills the Settings model list (embedding models are filtered out).
- Settings: new section with server, editable model list, Refresh and Test. The tray's Model menu gets the local model, and `SetBackend` handles the switch.
- `SyncBackendRadios` ticks exactly one backend radio after every change. The CLI radios live in an Expander that may be collapsed, where WPF doesn't untick grouped radios, so they're set by hand.

**Live typing** (`CaptureController.RunAsync`)
- `IAiBackend.AskAsync(…, onText)` is a default interface method; only the API backend streams. Pieces go into a `StringBuilder` and release a `SemaphoreSlim`.
- A local `PumpAsync` types what `OutputCleaner.LivePrefix` allows:
  - nothing while the answer could still turn out to be a code fence, thinking, a quote or a `$ ` prompt;
  - trailing spaces are held back.

  The first text stops the dots and erases them. `_shownLength` tracks what's on screen, so the failure path can still put your request back.
- At the end, the screen is reconciled with `OutputCleaner.Clean` (common prefix, backspace the rest, type the difference). A risky answer is backspaced and goes through the usual confirmation.
- `StreamAnswers` (default on) only applies to sentence and paragraph lengths, outside `OneLineOnly` apps, and not to code.

**Fixes**
- `OnKeyDown` swallows repeats of any Inkling shortcut while capturing, instructing or thinking. In a low-level hook the key's async state isn't updated yet, so "already down" means a repeat.
- `ChatApiBackend` stops reading at the first `finish_reason`. A rewrite on a slow night waited 11.6 s after a 10-token answer for the trailing usage chunk. `RequestTrace.LastOutputMs` and the thinking character count are now in the trace log.
- `PasteTextAsync` waits for the target window to answer `WM_NULL` (`SendMessageTimeout`, 2 s, abort if hung) before restoring the clipboard, instead of a fixed 250 ms. The pasted data carries `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory = 0` and `CanUploadToCloudClipboard = 0`, as before.
- `CaptureController.DotFrames(process)` uses `·` for `AutoCorrectApps`. `CountIsReliable` turns off retry there when the answer contains an AutoCorrect trigger.
- `AppConfig.OneLineApps` (Code, Code - Insiders, Cursor, Windsurf, VSCodium) and `OneLineOnly(process)` treat those like terminals for code and streaming.
- Dots: 300 ms per frame (was 130). The README GIFs match.

**Dev flags and benchmark**
- New `--rewrite "instruction" "text" [model]`.
- `--bench` accepts `local:<id>`, with no gap between questions (there's no rate limit to respect).
- The VS Code code questions no longer require multi-line answers.
