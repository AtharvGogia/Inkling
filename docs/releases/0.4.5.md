Inkling now knows what you're looking at: the page in your browser, or the file you have open.

## What's new

- **The page you're on.** In a browser, Inkling tells the model which page you're on, so "summarise this issue" or "what's the shortcut for this here" fit the page. Only the site and page are sent, like `github.com/AtharvGogia/Inkling-for-Windows/issues`. The part after `?` or `#`, where search terms and login or reset codes live, is never sent. Works in Chrome, Edge, Brave, Opera, Vivaldi, Arc, Firefox, Floorp, LibreWolf, Waterfox and Zen.
- **The file you have open.** In Word, Excel, PowerPoint, Notepad, VS Code, Notepad++, Acrobat and other apps that show the file in their title bar, Inkling tells the model the file's name and type, for example `notes.ps1 (a PowerShell script)`. Only the name is sent, never the folder it's in.
- **Answers that fit the file.** In a `.ps1` file you get PowerShell, in `.py` Python, in `.sh` bash, in `.sql` a query, and in `.csv` values that fit the columns, whichever app the file is open in.
- **Private windows are left alone.** Nothing about the page is sent from Private, Incognito or InPrivate windows.
- **You choose.** It's on by default, and you can turn it off in Settings → Privacy with *The page address or the open file's name*. The tutorial and the README's Privacy section describe exactly what's sent.

## For developers

**Page address** (new `BrowserUrl.cs`)
- `StartLookup(hwnd)` runs on a pool thread and returns a task at once, because it's called from the keyboard hook. `CaptureController.BeginCapture` and `BeginSelection` start it, so the address is read while the request is typed. `RunAsync` waits for it for at most 150 ms after Enter, then sends without it. Retries reuse the first request's context.
- The address bar is found through UI Automation: `AutomationElement.FromHandle(hwnd).FindFirst(Descendants, …)` for an Edit control with `AutomationId` `urlbar-input` (Firefox-based browsers) or `Name` "Address and search bar" (Chromium-based ones). If neither matches, for example in a browser in another language, it falls back to the first Edit control inside the first ToolBar. The value comes from `ValuePattern`.
- `Clean(raw)` keeps host, port (when not the default) and path, and drops `www.`, the query and the fragment. It adds `https://` when the browser hides the scheme, and cuts the result at 150 characters. It returns null for non-http(s) addresses (`chrome://`, `about:`, `file://`) and for text with spaces, which is a search being typed.
- Private windows are detected from the title ("InPrivate", "Incognito", "Private Browsing") and skipped.
- Results are cached per window for 30 s, keyed with the title, which changes when the tab does.

**Open file** (new `OpenFile.cs`)
- `FromTitle(process, title)` is a pure function over the window title. It makes no cross-process calls.
  - Office (`WINWORD`, `EXCEL`, `POWERPNT`): takes the first title segment. When Windows hides extensions, it adds the app's usual one. "Document1", "Book2" and "Presentation1" become "a new, unsaved document".
  - Notepad, Notepad++, VS Code, Cursor: "Untitled" is treated the same way.
  - Everything else: the first title segment (split on ` - `, ` — `, ` – `, ` | `) whose extension is in the known-types table.
  - It strips unsaved markers (`*`, `●`), Office status after ` • `, and Photoshop's zoom after ` @ `.
  - It keeps only the last part of a path, and returns nothing for segments with characters that can't be in a file name, such as an email subject "Re: report.docx".
- `Result.Describe()` gives `file "x" (type)` from a table of about 60 extensions.

**Context and hints** (`ForegroundContext.cs`, `AppConfig.cs`)
- `Describe(hwnd, cfg, url)` and `Compose(…, url, file)` add `, page "…"` or `, file "…" (…)` to the context. The open file is skipped for browsers and for private windows.
- `ContextRule` gains `Extension`. `HintFor` checks extension rules before the others.
- New default rules: `.ps1`, `.sh`, `.py`, `.sql`, `.csv`. `AppConfig.Load` tops up missing default rules by process plus extension, so existing configs get them too.
- New `AppConfig.SendOpenItem` (default true), with a checkbox in Settings → Privacy. Reset to defaults and the diagnostics line include it.

**Diagnostics and dev flags**
- The timings report has a new row, "page address (wait after Enter)": found, none, or "not ready in 150 ms" (`RequestTrace.UrlMs`, `UrlFound`, `UrlTimedOut`).
- New `--url-test [seconds]`: once a second, it prints the address read from the browser in front, already cleaned, and how long the read took. It sends no input. The README's developer-options table now lists it, along with `--caret-test` from 0.4.4.

**Tests**
- 108 unit tests (up from 69). New ones cover:
  - file names from Word, Excel, PowerPoint, Notepad, VS Code, Notepad++, Photoshop and Acrobat titles, including hidden extensions, unsaved markers and paths that must lose their folder;
  - new documents;
  - titles that name no file;
  - extension rules winning over app rules;
  - the context text;
  - address trimming, non-web addresses and search text;
  - long paths;
  - private-window titles.
- Checked for this release: the address lookup was tried live with `--url-test` in a browser. File names were checked only through the unit tests, not live in Word or Excel. Answers using the new context weren't benchmarked.
